# Fixtures

Every fixture in this repository is **synthetic and committed**. Nothing here is
a customer drawing, a customer rate or a customer bid, and nothing here is
generated at test time from a network call — a fixture that changes under you is
not evidence, it is weather.

## The policy

1. **Synthetic, not sampled.** A fixture is authored (or generated by
   `pnpm gen:fixtures`) so its expected answer can be derived by hand. If the
   only way to know a fixture's right answer is to run the code under test, it is
   not a fixture.
2. **Committed, not fetched.** Fixtures live in the tree. `pnpm verify` and
   `pnpm e2e` run with no network beyond loopback (C-07), and model calls are
   fixture-replayed (L-AI-01).
3. **Clearly labelled.** Anything a user can see that came from a fixture — the
   sample project of R-UI-033, above all — is labelled `SAMPLE` on screen.
4. **Named when missing.** A lane that needs a fixture it cannot find refuses by
   name with `FIXTURE_MISSING` and names the generator that makes it. It never
   quietly skips.
5. **Regenerable.** `pnpm gen:fixtures` is the one way a generated fixture is
   made. Regenerating must be byte-identical, or the fixture carries a timestamp
   it should not.

## What lives where

| path | owner | what it is |
| --- | --- | --- |
| `tests/e2e/support/seed.ts` | the e2e lane | the fixture tenants and users `scripts/seed.mjs` plants and the journeys assert against — one source, so the seeder and the assertions cannot drift |
| `tests/e2e/baselines/auth/**` | the e2e lane | committed Linux screenshots, compared at `maxDiffPixelRatio` 0.002, regenerated with `pnpm e2e --update-baselines` |
| `tests/lint-fixtures/<rule>/{bad,good}.*` | the lint lane | one deliberately-wrong and one deliberately-right file per NEVER; excluded from the tree-wide lint, linted on disk by the contract test |
| `fixtures/drawings/**` | the takeoff lane | not built yet — `pnpm gen:fixtures` names `F-RCC6` and skips with `LANE_NOT_YET_BUILT` |
| `fixtures/books/**` | the book lane | not built yet |
| `fixtures/bids/**` | the bid lane | not built yet |

## The e2e fixture set (AC-13)

`scripts/seed.mjs` plants, into the scratch database `cubit_e2e`:

- `owner@e2e.cubit.test` — OWNER of tenant `acme`
- `member@e2e.cubit.test` — MEMBER of tenant `acme`, OWNER of tenant `rival`
- both accounts pre-verified, both with a personal tenant, exactly as a
  signed-up account has one (R-SPINE-002)

`rival` exists for one reason: a tenant `owner` must never be able to reach. Two
tenants with real rows in them are what make the cross-tenant refusal in `V-DB`
provable rather than vacuous.

Journeys create their own accounts (`j000@…`, `j001@…`) with fixed strings —
fixed strings are what keep the committed screenshots pixel-stable.
