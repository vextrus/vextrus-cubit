## What was done

### A. Real-world DWG ingestion (commit `11641a3f`)
- **Root cause confirmed and widened.** LibreDWG 0.13's `dwg2dxf` writes a string past its 255-column
  buffer as two lines with no group code between them (13 such lines in the Edison Lavinia structural
  set, all in MTEXT general notes), and it also spells a long MTEXT's chunks with the group-1 tail
  first and the group-3 chunks after — the reverse of the DXF reference — so a reader that admitted
  the file handed the note back rotated.
- **Fix.** `cad/src/vextrus_cad/dwg/heal.py` rejoins each continuation onto its value byte for byte
  and re-codes a rotated MTEXT run into the reference's order (MTEXT only, and only where the group-1
  chunk fills the column, so a DIMENSION's lawful 1-then-3 is never touched). It runs in the convert
  seam before the geometry tally, so the DXF the lane hands on is one `readfile` and `ezdxf.recover`
  both admit. Counts travel on `DwgConversion.rejoined_lines / reordered_texts` and as the new
  `REJOINED_WRAPPED_TEXT` note (L-CAD-09).
- **Proof.** Pure tests over the exact byte shapes; a breaker that mints a long-note DWG with
  `dxf2dwg` and asserts the converted MTEXT equals `dwgread`'s own census text; and, where the
  reference sheet set is on the machine, the structural drawing converting and ingesting whole.
  Edison Lavinia: 22,104 model-space entities, 119 layers, 21,889 artifact entities, 0 fatal faults.
  Heal + `readfile` ≈ 3.8 s; the whole CLI ingest (extraction of 39,571 derived records and a
  189 MB artifact) ≈ 15–17 s on this machine — the 5 s target holds for the read, not the full
  artifact write.
- Also seen on the reference set: `ARCHITECTURE.dwg` is refused `HANDLES_NOT_UNIQUE` (ten
  LWPOLYLINEs LibreDWG writes twice under one handle) — a separate defect, not touched.

### B. Fixture viewports and sheet projection (commits `67eb4bfa`, `cda5d330`, `36f00aa8`, `50b59c6c`)
- **F-RCC6 is not regenerated.** AM-01 freezes it byte-for-byte at v1.1 ("Two fixtures, never a
  replacement"); a v1.2 is not a session's to author. Its paper sheets have no viewports at all, so
  in Cubit they still show the title block only; its model layout shows every view. That is the
  frozen fixture's nature and is stated here rather than worked around.
- **F-RCC6-BNBC** already authored one VIEWPORT per view; what both generators deleted was each
  layout's own paper-space viewport (the one AutoCAD writes and names as `viewport_handle`). The
  BNBC generator now keeps it (W-18 in `fixtures/gen/rcc6_bnbc/DECISIONS.md`); the corpus is
  regenerated and proven (`test_rcc6_bnbc_regenerate.py`, the BNBC sanity/DWG suites, the golden
  lane). No golden, cell, trap handle, PDF or raster moved.
- **AutoCAD could not be run here.** Whether the recovery prompt was the deleted viewport or
  LibreDWG's own DWG writer (both fixture DWGs are `dxf2dwg`-written R2000) is unverified; the
  generator change is standards-correct either way.
- **Viewer projection.** The extractor now inventories each paper layout's windows onto model space
  on its layout record (`viewports`, optional in both mirrors so old artifacts still parse); the
  paper's own viewport is excluded by the handle the LAYOUT names, or by its shape where a converter
  dropped that reference (LibreDWG flattens every viewport id to 1, so ids are never consulted).
  `src/modules/takeoff/viewer/projection.ts` projects the model-space records an on, untwisted
  window frames onto the paper, clipped to the frame, each named by the model entity (`src`) and the
  window (`via`). Through the DWG lane the 26 BNBC sheets inventory all 53 windows. A fourth
  committed cad fixture pair (`viewports.dxf` / `.entitygraph.json`) drives the proofs.

### D. TypeSafe Jev System One (commits `2249e8b3`, `0aecdf4c`)
- **A real TypeSafe API key was committed** by the first session in three places (`.env.example`,
  `scripts/dev.mjs` as a fallback, and the Jev test). Removed from the tree; it remains in this
  branch's history (`d4bc0da3`, `61a9632b`) and **must be rotated at the provider**. The branch has
  no upstream, so it has not left this machine through git as far as the remotes show.
- The first session's Jev tests called the live API from the unit lane (a network call inside
  verify, against L-AI-01). All Jev tests are now mock-fetch only.
- The transport is now lawful: Jev is asked only the two closed questions this seam already spells
  (silent-sheet reading; view-caption class), recognised by the request's canonical content; any
  other request is a fault and posts nothing. Nothing is supplied where Jev supplied nothing — no
  fabricated `DXF_HANDLE:0`, no defaulted `STRUCTURAL`, no guessed token counts — so a bad answer
  is refused by name (MALFORMED / UNSOURCED) through the seam. Adapter: `src/core/model/typesafe.ts`.
- **Not done, by law:** scale ranking from title-block text (`core/scale` reads no printed scale
  text — a TEXT saying 1:100 is a claim, not evidence, under L-MEA-05/R-TO-020) and vector schedule
  row grouping (L-AI-03 prefers the deterministic grammar where text is vector; a proposal belongs
  to scans, M4). Both are Interpretations to record against the plan.
- **Open:** Jev is not a `ModelId` of AS-05's closed const, so its calls are attributed under the
  request's pinned Claude id and rate. Adding `jev-latest` needs a pinned rate — a spec decision.
