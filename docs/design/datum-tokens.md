# Design Decision — datum-tokens

Not a routed screen. This document fixes the Datum token sheet — every variable name and both
theme values — and the BasisMark primitive. It is the contract for `src/ui/tokens.ts`,
`src/ui/tokens.css`, `src/ui/globals.css` and `src/ui/basis.tsx`. The `/design` gallery that
renders this sheet ships later under R-UI-011; R-UI-050 screen states therefore do not apply
here (§8 covers the one runtime state BasisMark owns).

## 1. Emission shape (R-UI-001)

`renderTokensCss()` emits exactly three blocks, in this order, and `src/ui/tokens.css` is that
string committed verbatim:

1. `:root, [data-theme="light"] { … }` — light values.
2. `[data-theme="dark"] { … }` — dark values, same key set (theme flip is total).
3. `@media (prefers-reduced-motion: reduce) { :root, [data-theme="light"], [data-theme="dark"] { … } }`
   — every `--motion-*-duration` set to `0ms` (R-UI-004). The triple selector keeps equal
   specificity with both theme blocks so last-in-file wins regardless of theme attribute.

Formatting law (so the renderer is deterministic and diffs are readable): one leading comment
line `/* Generated by renderTokensCss() — edit src/ui/tokens.ts, never this file. */`; two-space
indent; one `--name: value;` per line; groups in the order of §2–§4 below, keys in the order
listed there; a blank line between groups; opaque colours as uppercase 6-digit hex; alpha
colours as `rgba(r, g, b, a)`; trailing newline.

Roles are theme-stable: `--graphite-0` is always "app background", so dark mode flips values,
never consumer code.

## 3. Non-colour tokens (identical values in both theme blocks)

- Spacing (4-pt grid): `--space-1: 4px` through `--space-12: 48px`, each `--space-<n>` = n×4 px.
- Radii: `--radius-2: 2px`, `--radius-4: 4px`, `--radius-8: 8px`, `--radius-12: 12px`.
- Hairline: `--hairline: 1px solid var(--graphite-200)` — the var() reference resolves per
  theme, so the value string is the same in both blocks. Hairlines are preferred over shadows.
- Fonts (named, not loaded — the shell increment loads them):
  `--font-ui: Inter, 'Helvetica Neue', Arial, sans-serif`;
  `--font-mono: 'JetBrains Mono', 'SF Mono', Consolas, monospace`;
  `--font-doc: 'Noto Sans', Inter, Arial, sans-serif`.
- Type scale (R-UI-003): `--text-12: 12px`, `--text-13: 13px`, `--text-14: 14px`,
  `--text-16: 16px`, `--text-20: 20px`, `--text-24: 24px`, `--text-32: 32px`;
  `--leading-ui: 1.45`; `--weight-heading: 600`, `--weight-body: 400`,
  `--weight-body-medium: 500`.
- Motion (R-UI-004): `--motion-state-duration: 160ms` (inside the 120–200 ms band),
  `--motion-panel-duration: 240ms`, `--motion-flyto-duration: 320ms`,
  `--motion-ease: cubic-bezier(0.2, 0, 0, 1)` (decelerating, no bounce),
  `--motion-flyto-ease: cubic-bezier(0.45, 0.05, 0.25, 1)` (ease-in-out for camera travel).
- Z-layers, exactly four: `--z-base: 0`, `--z-sticky: 100`, `--z-overlay: 200`,
  `--z-toast: 300`.
- Breakpoints: `--breakpoint-sm: 640px`, `--breakpoint-md: 960px`, `--breakpoint-lg: 1280px`,
  `--breakpoint-xl: 1680px` — a drawing workspace earns its widest tier.
- Density rows (R-UI-005): `--row-comfortable: 36px`, `--row-compact: 28px`.

## 5. globals.css (R-UI-001 — no literal anywhere in this file)

`@import 'tailwindcss';` then `@import './tokens.css';`. The `@theme` block exposes, via
`var(--…)` references only: every §2 colour under Tailwind's `--color-*` namespace keeping its
Datum name (`--color-graphite-0: var(--graphite-0);` … through canvas), fonts as
`--font-sans: var(--font-ui)`, `--font-mono: var(--font-mono)`, `--font-doc: var(--font-doc)`,
and the four breakpoints as `--breakpoint-*: var(--breakpoint-*)`. Nothing else enters
`@theme`. One utility:

```css
.numeric {
  font-family: var(--font-mono);
  font-variant-numeric: tabular-nums slashed-zero;
}
```

## 6. BasisMark (R-UI-002)

The colour+glyph pair as one primitive; chips, table cells, sheet overlays and documents adopt
it in their own increments. Pairing, fixed: MEASURED ◆ · TRANSCRIBED ▣ · DERIVED ƒ (U+0192) ·
IMPORTED ⇩ · ENTERED ✎ · INTERPRETED ▦ · DEFAULTED ○.

Rendered markup for `<BasisMark basis="MEASURED" />`, exactly:

```html
<span data-testid="basis-mark" data-basis="MEASURED" role="img" aria-label="Measured"
  style="color:var(--basis-measured);font-family:var(--font-mono);line-height:1">◆</span>
```

- The glyph is the entire text content; the accessible name is the `aria-label` from the string
  table (`role="img"` so the label is announced); no other string literal in the JSX.
- Inline style carries only `color`, `font-family` and `line-height: 1` — size inherits (1em)
  so the mark scales with its host (chip, 13 px table cell, document) and never disturbs the
  36/28 px row rhythm. Mono keeps marks column-aligned in tables.
- Greyscale survival (J-004 checkpoint): the glyph alone distinguishes all seven; colour is
  reinforcement, never the only signal (R-UI-060).
- Unknown code: `BasisMark` throws `Error` with message `Unknown basis code: <value>` — a
  developer error surfaces at build/test time; a wrong basis must never render as a plausible
  mark.

## 8. States and motion

No routed screen, so R-UI-050's screen states are owed by the `/design` gallery increment, not
here. The one runtime state this increment owns is BasisMark's unknown-code throw (§6). Motion
this increment ships is tokens only (§3); the reduced-motion block (§1) already guarantees that
any future consumer of `--motion-*-duration` is inert under `prefers-reduced-motion: reduce`.

## 9. Both themes — summary of what differs

Graphite, cobalt, semantics, basis, element, canvas and the four shadows carry distinct dark
values (§2, §4). Spacing, radii, hairline (by reference), fonts, type, motion, z, breakpoints
and rows are byte-identical across both blocks — but every variable is emitted in both, so
`cssVariables('light')` and `cssVariables('dark')` have identical key sets and a theme flip
strands nothing (J-004 checkpoint).

## 10. Test hooks
