# M0 "Drawings in": the plan

Drafted by the orchestrator on 26 Sep 2026 from the signed spec (docs/specs/M0.md), to be attacked
by four reviewers (architecture, QS, UX, refuter) and resolved with the owner before tickets are cut
(docs/sdlc.md). The spec fixes the scope; this page fixes the order, the files each ticket owns, the
test seams, the Checks and the risks. Terms are CONTEXT.md's.

## The shape of M0's code
- **Backend:** one uv project; `vextrus/` holds the 12 Django modules and `engine/` (no Django).
  Each module keeps ADR 0034's anatomy, with one change to stop parallel tickets colliding on one
  file: **`services` and `http` are packages** (`services/__init__.py` re-exports; each ticket owns
  its own submodule, e.g. `platform/services/jobs.py`). Adding a re-export line is the only shared
  edit, and it is a trivial merge.
- **Engine:** `engine/read/` (reader interface; `libredwg/`, `acadsharp/`, `pdf/`, `sandbox.py`),
  `engine/recognise/` (`sheets.py`, `views.py`), `engine/render/` (`buffers.py`, `fonts/`,
  `text.py`), `engine/check/` (one file per Check), `engine/register.py`, `engine/export.py`.
  M0 has no Element Families yet (`engine/families/` arrives with M1's first family).
- **Frontend:** `web/` (Vite, React 19, Tailwind v4 tokens from docs/design/system.md); features by
  folder (`web/src/app/`, `web/src/sheet/`, `web/src/takeoff/`, `web/src/projects/`,
  `web/src/format/`), each ticket owning its folder.
- **Harness:** `scripts/score/` (vx-score, installed to `/usr/local/bin/vx-score` by the owner),
  `scripts/real-drawings` (the owner's command), `.github/workflows/`.
- **Migrations:** each module's own chain; at most one ticket per wave adds a migration to a given
  module (ADR 0025); CI checks one leaf per module and `makemigrations --check`.

## The order (waves), with the files each ticket owns

Wave sizes follow ADR 0025: wave 1 is four cloud and one local; a wave widens only when wave 1's
gates held (review queue under a day, at most one PR in four needing a second continuation, trivial
conflicts). Effort `high` unless marked. "Owns" lists the paths a ticket may create or change; it
touches nothing else except a re-export line.

## Test seams (highest first; from the spec)
1. The owner's walk on the reference setup, both Development Sets.
2. The real-drawing check (`local`, as `vxkeys`, aggregates only), required on every engine PR.
3. The HTTP API on real Postgres with RLS on and the app's non-owner role, jobs run in the test: one
   whole-Step-1 test on a synthetic DWG (ticket 21), and each ticket's own API tests.
4. The engine's public functions on committed synthetic fixtures.
5. One browser smoke test (if Chrome runs in the cloud VM; else local).

## The Checks M0 brings (ADR 0027; each names M0)
Two decoders agree (quarantine + `file_misread` Question) · Bangla text in a legacy ANSI font (flag) ·
the drawing register against the sheets found · the Plot's pages against the sheets found · storey in
the title against storeys in the view titles · Coverage (no view unaccounted: used, excluded or
assigned).

## Risks and how the plan meets them
| Risk | Where | Response |
|---|---|---|
| Segmentation and views are fitted to two sets and fail on the next | 13, 17 | tuned only on Development Sets; stop when n / N stops improving; M1's Held-out Set is the proof |
| bwrap will not run inside the cloud VM | 04 | the sandbox tests mark "needs bwrap" and run locally; the cloud runs the adapter unsandboxed in tests only, never in the product |
| A single-stroke SHX font with a clean licence does not exist in a usable form | 11 | fall back to an outline substitute and record the width error in the font report; the render check's F1 shows the cost |
| Shared files collide across parallel tickets | all | 01 writes every shared file once; services and http as packages; one migration per module per wave |
| The credit expires before the cloud tickets run | 02–22 | waves 1–2 are cloud-heavy and start the day 01 merges |
| The owner's review becomes the bottleneck | all | waves sized by ADR 0025's gates; PRs lead with what was not verified; the owner reads only `.github/`, `.claude/`, migrations and tests in full |
| The real-drawing check is slow (both sets, every engine PR) | 06, 13–18 | per-sheet steps are keyed and cached by input hash; the check reruns only changed steps |
| The Edison key drafted from PDFs inherits the PDF's losses | 06 | the owner confirms it sheet by sheet; it counts sheets, titles and views, not text content |
